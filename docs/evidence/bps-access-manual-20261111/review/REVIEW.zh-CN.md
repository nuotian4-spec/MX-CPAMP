## 页面请求触发

- `BPSModelsPanel` 挂载及局部刷新读取发布配置、管理设置与凭证列表，不查询官方 access。只有点击“获取官方允许模型”才发起一次 access；保存只写模型字段并读取配置。
- `BPSAccountModelsSummary` 挂载只读取发布配置；只有点击“查询本凭证官方权限”才另发一次 access。系统设置与账号页的权限观察分别位于组件内存，切换页面不共享结果。
- 浏览器或服务端启动 BPS 巡检会按凭证另发 access；本轮不启动巡检。

精确步骤采用系统设置中一次发现：新手工 OAuth → 系统设置选唯一 BPS 凭证 → 点击一次官方模型发现并记录权限、目录和时间 → 一键选用草稿 → 人工保存 → 账号模型页仅查看发布/注册，不再次查询官方权限。账号页此时显示官方权限未确认，符合页面内存隔离边界，不要求为补齐计数再发请求。

## 独立审查结论

手工验收入口准备通过，可由主会话整合交付；真实官方 access 与模型页面结果仍待用户执行。

- `start` 只启动空本机面板，不创建 OAuth，不调用官方 access。固定镜像、回环随机端口、共享 namespace、根只读、空 tmpfs、无旧挂载、无 Worker、无容器日志与归属清理均在脚本中保留。
- 唯一真实 access 位于系统设置。README 要求允许且非空时全部选用并人工保存；受限、错误、空目录或未确认均停止保存且不重试。账号页只核发布与注册，不再查询官方权限，不启动巡检。
- `verify` 仅读本地保存、注册和发布配置，不调用官方 access、刷新或推理。账号秘密仅在工具进程内作存在性和身份匹配判断，公共回执只输出数量及布尔，不保存目录、邮箱或上游身份。
- 页面观察保留 `manual_observation_is_user_report=true`。通过条件要求唯一 active BPS、保存注册一致、官方发现数等于发布与注册数、人工报告恰好一次允许查询并保存；缺观察或未完成时为 `pending`。退出码 `0` 仅表示核验工具完成，不等于业务通过。
