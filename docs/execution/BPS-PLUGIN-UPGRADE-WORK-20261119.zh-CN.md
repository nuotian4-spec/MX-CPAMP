| 责任范围 | 交付条件 |
| --- | --- |
| CPA 插件宿主 `internal/pluginhost` | 从注册与重新配置共用的配置副本中剔除**顶层** `store`。磁盘选版与插件业务字段（含嵌套同名键）原样保留。首次注册失败的实例不标记为已注册，再次应用时仍执行首次注册。 |
| CPA 安装与恢复 `internal/pluginstore`、`internal/api/handlers/management` | 只隔离本轮新建且失败的候选；恢复被覆盖文件和旧配置，保留原先停用状态。任务详情与最近任务保留已记录的失败原因。旧版本没固定版本号时也要能在重启后被选回。 |
| Manager 插件页 `apps/web` | 未注册时提示查看本轮安装错误，不画授权码输入框；已注册而许可查询失败时显示查询失败；供应商明确返回 `license_activation_required` 时才提示激活。切换活动实例后读取其许可状态，不改许可数据。 |

**一次集成验收。** 实现者仅跑覆盖所改分支的专项。用同一份最终 Linux 候选构建，在本地隔离环境走真实网页 ZIP 后端，依次从 `0.5.58` 升至 `0.5.62`、再升至 `0.5.85`；每次核对实际注册版本与许可 GET。用一个失败候选验证回退、同挂载重启后的活动版本及失败原因。授权框按未注册、待激活与已激活三个关键状态验收；使用模拟许可响应，不使用真实授权码。真实有效许可的续用不记作离线已验。

根因对照不复跑，不调用真实模型，不做数据库迁移。本轮无需重复全仓测试。所有结果只引用与最终候选相符的回执。

## 本地验收回执（2026-11-19）

本地候选基于 `07dc177`。CPA 使用 Linux/amd64、CGO 开启的服务端构建，在 RC3 运行环境中测试；容器禁用外网，不使用现场凭据。ZIP 请求调用管理页面实际使用的预览和安装接口，不代替生产浏览器验收。

| 场景 | 实际结果 |
| --- | --- |
| 原版 0.5.58 连升 0.5.62、0.5.85 | 两次目标文件、活动元数据、注册与启用状态均符合预期。两次许可 GET 均为 200、`license_activation_required`。 |
| 新候选加载失败，旧版没有版本固定配置 | 任务为 `failed`，说明旧配置及活动实例已恢复。失败文件保留为 `.so.failed-<任务ID>`；0.5.58 当场可查询，同一容器和数据重启后仍注册为 `0.5.58-dev`、许可 GET 200。 |
| 宿主与管理接口 | 专项覆盖只过滤顶层 `store`、保留嵌套配置及选版，失败后再次首次注册、停用意图、并发变更保留与回退。 |
| 管理页面 | 许可组件 11 例通过；提示更新后只补跑 4 个直接相关用例。未注册或许可读取失败时无授权码输入；明确待激活时可输入，激活后的有效状态单独显示。 |

本地原始回执：`$env:TEMP/mx-bps-fixed-3dc9aa80`，连续升级和失败重启的输出分别为 `good-result.txt`、`bad-result.txt`。真实有效许可在生产更新后的续用尚未验证。
