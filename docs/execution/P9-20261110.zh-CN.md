## A：CPA BPS 运行时与 v8 授权

### WHY

BPS 是独立授权与请求协议；只有登录按钮没有执行、刷新与模型调度不能交付。CPA 统一持有凭据、刷新和请求生命周期。

### WHAT

1. 独立 `bps` provider、Excel client、token endpoint、原子存储与刷新；绝不伪装 `codex`。
2. BPS Executor 接入现有 registry、mixed 调度、payload finalizer、用量和错误处理；首期文本 HTTP Responses/Chat Completions 与 SSE。
3. 新增 v8 BPS OAuth 与 Codex/BPS受控内存凭据导入，状态、取消和必要身份校验；优先现有 Interface，不扩展 v0。
4. 对 WS、previous_response_id、加密/工具/状态历史做真实能力过滤和必要账号绑定，不能因同名模型注册破坏原 Codex。
5. 一份具体管理契约，先发送给 B 线，后续契约修改显式同步。

### WHERE

只改本线 worktree 的 `components/cpa/**`，以及 `docs/contracts/cpa-login-v8.md`、`docs/evidence/cpa-runtime/**`。CPA v8与公共运行时文件由 A 单写。

### HOW MUCH

先完成可编译纵切与专项证据，再补协议范围；不能仅列待办。遇阻5分钟内报告具体阻塞，约30分钟给首个可核证检查点。同类失败第二次先复现再修，不让主会话盲重试。

### DONE

- 列明新增测试并跑受影响包的专项命令；build `./cmd/server` 成功；记录路径、命令、退出码和输入提交。
- 假上游验证 client隔离、刷新轮换、token不串写、混合调度、模型去重、SSE完整结束/中断及payload配置最后生效。
- Codex相关路径定向回归、diff-check；真实登录/BPS调用仍标待证。

### DON'T

不改 CPAMP/登录容器/根发布文件；不搬 Sub2API 数据库；不硬编码历史默认模型为当前能力；不删除 refresh_token；不读真实凭据、不访问生产；不 push。

## B：CPAMP 四入口、内部登录 Module 与本地集成

### WHY

管理员需在既有面板导入两通道账号，登录材料仅当次使用；登录协议依赖与模型执行隔离。

### WHAT

1. Codex OAuth保留；新增Codex 2FA、BPS OAuth、BPS2FA；单profile授权，账号列表通道与补登录状态准确。
2. CPAMP内存任务、管理员鉴权、明确v8路径/方法、账号mutation协调；不把token返回浏览器。
3. 单任务内部登录容器，复用供体协议核心与Codex/Excel Adapter；凭据通过stdin/私有pipe，不用argv/env/文件/checkpoint保存秘密。不使用第三方重登服务。
4. 取消/超时终止任务进程组，导入以CPA真实结果为准；明确失败码，不记录原始secret/异常/回调URL。
5. 构建文件、独立锁文件、许可、脱敏Compose/Caddy/config模板。部署模板不覆盖现有服务器。

### WHERE

只改本线 worktree 的 `components/cpamp/**`、`components/oauth-login/**`、`deploy/**`、`docs/contracts/login-worker.md`、`docs/evidence/manager-login/**`。不改A的CPA或契约文件。

### HOW MUCH

先按A契约推进，用假服务并行测试，无需等真实OAuth。首个可核证检查点约30分钟；涉及不可验证的BPS手工回调须保留待证而不是删除入口或宣称业务成功。
