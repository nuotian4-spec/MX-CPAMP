# BPS 原生授权页：从只读预览恢复交互

基线：Manager `v2026.11.19-rc.2`、插件包 `0.5.86`。本地候选已验证，未部署。

## 现状

- `PluginResourcePage.tsx` 对 BPS 授权页设置脚本禁用的 iframe 沙箱，在加载后禁用表单控件、移除链接。菜单路由已恢复，操作仍被宿主禁用。
- 插件库内置的页面与 ZIP 配套面板都使用 `bps-management-hello/ready/request/response` 消息。原生页向父页面申请 `start`、`callback`、`status`；当前 Manager 的 `pluginHostStyle` 只负责样式。仅解禁输入框不构成接入。
- `oauth.ts` 已有 BPS 可复用的启动授权、提交回调、查询状态接口。原生页凭 `status=ok` 即显示“CPA 已保存账号”，而当前 Manager 对 BPS 还检查 `saved` 与 `adopted`。
- 邮箱密码代登录是独立能力。原生页识别 `auto-login-v1`；ZIP 单列辅助服务，包内说明其运行与 CPA 生命周期有关。页面版本、插件注册、商业许可均不是此服务已就绪的证据。本轮没有探测生产服务。

## 手动授权的实现选择

目前部署通过 Manager 自己的域提供插件静态资源。0.5.86 的手动表单在 HTML 中已经存在，并非由 `app.js` 动态生成。因此本次选用**原生控件 + 宿主事件处理**：保留真实原生页面、样式与已有备用入口；由 Manager 接管手动操作，不运行供应商脚本、不需要新的资源域名，也不传递管理密钥。这个方案不实现整套供应商消息协议。

1. 只在已连接且已启用的 BPS 菜单中核对实际 iframe 文档地址和控件；其余页面不接管。浏览器跨域或新版缺少必要控件时保留可用的 Manager 手动 OAuth 备用入口，不给用户一个看似可用的假表单。
2. 生成授权链接、提交回调、查询状态分别走已有的固定 OAuth API。将回调与本次连接和 `state` 绑定，不跨连接处理旧回包。仅在用户点击时打开核对过的上游授权地址。
3. 提交回调只表示 CPA 已收到回调。仅在 `status=ok`、`saved=true`、`adopted=true` 时显示成功；未确认时允许继续查询。
4. 邮箱密码自动区保持不可输入。若未来确需运行完整供应商页面脚本，另行评估独立资源源站与有限消息协议；这既不是本次手动恢复的前置条件，也不等于已接入自动授权。

## 验收

- 仅用 `0.5.86` 原生页面与合成账号数据做一条浏览器闭环：点击授权、打开链接、粘贴回调、查询状态，确认成功提示与 CPA 保存并注册的结果一致。
- 同一流程模拟未注册和缺少辅助服务：前者不能误报成功；后者不能阻断手动授权，也不能提交敏感输入。非本次页面或非本次状态不受理。
- 不按插件版本号分支。保留手动控件结构和 OAuth 接口的后续 ZIP 可复用；若供应商重做页面结构，则走备用入口。生产页面点击、真实账号登录、商业许可和模型推理不计入离线验收。

### 本地结果

`components/cpamp/apps/web/joint-tests/bpsNativeManual.browser.mjs` 在 Chromium 加载 0.5.86 包的原生 HTML 和候选 Manager 页面。每个场景生成一次链接、打开一次新标签页、提交一次回调并查询一次结果；上游页面和 CPA 接口均由本机模拟。

| 模拟 CPA 结果 | 原生页实际显示 |
|---|---|
| `status=ok, saved=true, adopted=true` | 授权成功，CPA 已保存并注册账号 |
| `status=ok, saved=true, adopted=false` | 尚未确认保存并注册 |

两个场景均验证回调输入在提交后清空、自动区不可输入、插件脚本未执行。4 项直接相关单测、项目 TypeScript 检查及 Vite 生产构建通过。

### 发布审查

2026-11-20 菜单发布专项审查通过。组件范围为 6 个实现或文案文件、3 个测试文件、1 份手册；复用同一候选的既有验证。已核对同源文档与禁脚本沙箱、连接切换清理、本次状态绑定及保存和注册的成功判定。CPA 后端、数据库与辅助登录服务不在本次变更中。

浏览器验收中的样式响应为空，因此该证据验证交互而非视觉效果；真实账号登录仍待生产使用确认。固定候选版为 `v2026.11.20-rc.1`，通过既有发布工作流构建。
