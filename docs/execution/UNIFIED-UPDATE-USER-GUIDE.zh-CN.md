# 插件 ZIP 导入与网页内核更新使用说明

适用对象：本站 MX-CPAMP 固定发行候选。功能交付、验证和现场接入状态以 `UNIFIED-UPDATE-IMPLEMENTATION-20261116.zh-CN.md` 为准；本文不是已部署回执。

## 选择更新对象

| 要做的事 | 入口 | 更新范围 |
| --- | --- | --- |
| 导入供应商提供的插件 ZIP | `/plugins` 现有插件页的“上传 ZIP” | 预览后安装包中指定的插件库，保留本站面板 |
| 更新本站内核发行 | `/system` 系统页的“核心更新” | 已适配的本站固定版本及其声明的应用组合 |
| 查看官方 CPA 新版 | 系统更新的官方版本信息 | 只检查版本，不自动替换本站定制内核 |
| 更新中断后恢复 | 更新任务详情及受控服务器恢复入口 | 根据同一轮次的实际阶段恢复，不重新发起相同维护 |

先确认当前 CPA 连接。预览候选和更新任务属于该连接对应站点；切换连接后重新检查，不把另一个站点的候选直接用于当前站点。

原 `/system/updates` 入口继续保留；它不替代本次核心更新入口。凭证页面及原有可用状态、最近请求、历史用量、额度、操作区域不在本次改版范围。

## 上传插件 ZIP

1. 在插件页上传 ZIP，查看插件 ID、包版本、平台、当前启停状态、许可要求、兼容性和阻止原因。上传及预览不启用插件，不执行包内脚本。
2. 核对维护影响后确认安装。静态条件合格但兼容资料不足时，需额外明确接受“兼容性未验证”；该确认仅作用于本次固定候选，不形成长期跳过设置。
3. 需要许可联网的包单独确认相应影响。没有许可证据时，页面保留“许可待验证”，不把文件落盘当成业务可用。
4. 在原任务中查看安装、宿主注册和实际活动版本。关闭抽屉或刷新页面不是取消已开始的安装，也不要因此再次上传或安装。

错平台、库身份不符、包内容损坏和已知不兼容属于拒绝安装。兼容性未验证与已知不兼容是不同状态。取消未安装的候选只撤销该候选，不移除现有插件。

已活动插件如果版本和安装路径相同、实际库内容不同，不按普通热更新覆盖；需要受控维护与重启。相同文件无需重装，不能仅凭相同版本号认定新包已经运行。

升级保留插件稳定 ID、既有 provider、配置、许可材料和原启停意图。原来停用的插件升级后仍停用。供应商 ZIP 中的整套面板、安装脚本、配置工具及烟测程序不作为本站安装步骤运行。

## 网页更新内核

首次使用由操作者安装受限宿主触发器并登记站点。设置页显示当前站点、实际运行版本、官方观测版本和本站可安装发行。只有官方版本领先时显示“待适配”，不直接覆盖官方镜像。

日常更新流程：

```text
检查版本 → 选择本站固定发行 → 预览站点与维护影响 → 网页确认一次
→ 后台预检与准备 → 停态备份与切换 → 内网健康检查
→ 按本轮确认范围恢复入口 → 查看任务终态
```

后台任务由独立宿主进程执行，Manager 重启或浏览器断开后仍可继续；恢复连接后查询原任务，不盲目重放。页面确认的是固定目标和当时的活动基线；基线变化时重新预览，不能把后出现的新版本替换成本轮目标。

### Manager 重启后查看原任务

1. 等待 Manager 恢复可访问，重新加载管理页面；未记住管理凭据时，按原登录规则重新登录。
2. 核对仍是原 CPA 连接及站点，进入原插件页或系统页。页面取得新连接引用，再读取持久化任务与原任务编号。
3. 以原任务的阶段、活动版本和完成结果为准；不再次点击安装来恢复显示。

Manager 的连接引用属于该进程。重启后旧页面可能收到 409，这不等于宿主更新失败。若操作者改过保存的 CPA 地址或密钥，旧引用同样失效；页面不会静默改绑或重发操作。需要查原任务时应恢复到原站点后重新打开页面。

核心更新与插件安装、删除、启停及相关配置切换共用站点维护门禁。另一个写操作正在进行时等待其终态，不从旧商店入口绕过维护。

## 结果怎么看

| 展示结果 | 实际含义 | 下一动作 |
| --- | --- | --- |
| 已预览 / 待确认 | 候选已固定，尚未开始安装 | 核对目标及影响后确认或取消 |
| 安装中 / 重载中 | 文件或宿主切换仍在进行 | 查询同一任务，不重复提交 |
| 已安装且保持停用 | 新版本已安装，保留原停用状态 | 需要使用时另行启用 |
| 许可待验证 / 许可异常 | 安装状态与许可状态不同 | 按插件许可入口处理，不重装代替授权 |
| 待确认重启 | 剩余动作超出本次已确认的维护范围 | 核对影响后明确授权 |
| 待恢复 / 失败 | 更新尚未达到成功终态 | 保留任务、日志与备份，按阶段恢复 |
| 更新完成 | 本轮安装及规定健康检查完成 | 真实登录、模型及供应商业务按另行验收记录判断 |

更新检查失败显示异常和上次观测时间，不等于“已是最新”。宿主未登记、暂不可达和维护任务失败也要分别处理。

## 既有业务保持规则

- **三类客户端 Key**：Kilo、Codex、BPS 独立通道策略继续有效；推理 Key 不获得更新管理权限。更新过程不创建、替换或展示真实 Key。
- **账号与续轮**：保留账号稳定引用、手工停用、会话最小绑定及已存配置；不恢复旧进程在途数、连接对象或代理占用计数。更新不触发真实登录或模型测试。
- **代理与出口**：保留出口绑定、固定 IP 历史、独占关系及容量配置。维护结束后以实际运行状态重新形成占用；不为更新隐式切换出口、增加直连或重放旧请求。
- **额度**：保留 Codex 来源绑定和独立导入材料、更新时间及未知状态。插件许可、来源额度和 Kilo 实际权益分别显示；更新成功不等于额度恢复，不覆盖人工停用。
- **恢复**：沿本轮实际备份、完整 Compose 链和活动发行指针处理。失败保留现场，不自动回灌数据库、不清理旧轮次、不使用单份基础 Compose 覆盖活动组合。

## 维护与已知限制

内核更新会中断相关服务；具体应用、入口和重启范围以确认页为准。失败后保全策略可能让入口和应用保持停止，需要按任务详情中的恢复材料处理。

首次宿主接入、生产维护、真实供应商许可、登录及模型验收需要对应授权。当前真实 BPS 0.5.58 的静态包检查不代表宿主兼容、许可或业务通过；本地合成测试不代替这些回执。本站不主动回退付费 API 或 Kilo credits，上游内部计费限制另行核实。

部署与恢复命令使用同一候选的 `deploy` 文档和固定版本材料；不从本文复制示意版本进行实际生产更新。

首次接入及恢复：`deploy/README.update-host.zh-CN.md`。常规命令恢复入口：`deploy/README.update.zh-CN.md`。独立 bootstrap 包只含宿主脚本、两份 systemd 单元和说明，不携带镜像、站点配置、账号或数据库。
