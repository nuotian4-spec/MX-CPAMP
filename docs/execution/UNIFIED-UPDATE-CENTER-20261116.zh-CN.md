# 网页内核更新与插件 ZIP 更新方案

日期：2026-11-16（CST）。范围：设计与实施入口。用户已选择网页确认维护影响后直接执行更新，服务器命令仅作为恢复入口；本次选择不包含宿主安装或线上更新授权。

## 1. 当前结论

上传 ZIP 更新插件的页面入口尚未开发、未部署，因此当前页面看不到。现有插件商店的固定来源安装能力与本地 ZIP 导入不是同一功能。

本方案统一两类更新的页面体验、版本状态、维护互斥及回执，但保留各自已有执行链：内核更新复用本站 `mx-update`；插件更新复用现有商店安装服务和 CPA 插件宿主。不再提供另一套插件安装器，不替换本站管理 UI。

| 能力 | 已核事实 | 本轮交付边界 |
| --- | --- | --- |
| 本站固定版本构建与发布 | 已发布源码包含 GitHub Actions 和三角色发行资产 | 继续复用，不重新建立发布体系 |
| 宿主一键更新命令 | 已有 `mx-update`，串联预检、备份、切换、健康及入口恢复 | 服务器首次站点登记尚未执行；源码存在不代表现场已经接入 |
| 网页直接执行内核更新 | 尚无对应闭环 | 待开发管理接口、独立宿主任务、状态读取与页面 |
| 插件商店固定版本安装 | 已有商店、安装服务及宿主逻辑热替换 | 保留；补齐与核心维护共享的后端互斥及实际运行状态 |
| 本地 ZIP 上传安装 | 尚无入口；现有商店要求库位于归档根目录 | 待开发上传、预览、指定库规范化及安装衔接 |
| 本次 BPS 0.5.58 包 | 已静态核对包内容和内部清单 | 尚未验证该二进制的实际加载、许可、热替换与本站版本配对 |

事实输入为本站已发布源码 `9dce11c613c5bc2c45d922cd2c021a7d5bba7a25`、发行 `v2026.11.16-rc.2` 及两份专项调查。它们不是本轮实时服务器观测；页面最终必须读取实际运行状态。

## 2. 页面与交互

不新增主导航，不调整凭证页的可用状态、最近请求、历史用量、额度和操作五块，不改变全局主题与默认密度。

### 设置页：系统更新

沿现有设置页加入紧凑更新区域，默认展示：

- 当前运行的本站版本及其内含 CPA 版本。
- 官方 CPA 最新观测版本、检查时间。
- 本站可安装版本、适配状态及简短更新说明。
- `检查更新`、`更新至指定版本`；进度和详情在同一区域展开。

官方有新版而本站尚未适配时，显示“上游有新版 · 待适配”，不提供直接覆盖官方镜像的按钮。检查失败显示异常和上次观测时间，不显示“已是最新”。

点击更新只确认一次：固定目标本站版本、CPA/Manager/Worker 的实际变更、维护范围、入口恢复规则和失败停态。提交后展示同一任务的阶段、开始时间、当前结果；Manager 重启时提示重连，页面回来读取原任务，不再次发起更新。

### 插件页：原插件卡片与商店

在现有 `/plugins` 页面工具栏明确显示 `上传 ZIP`，在 BPS 卡片保留 `检查更新`、`更新`、`查看记录`。设置页只展示插件更新摘要并链接到该入口，不复制第二套安装表单。

上传后打开一个预览抽屉：插件身份、当前活动版本、包版本、平台、兼容结论、是否需重启、许可联网影响。提供 `取消` 与 `确认安装`；展开详情再看实际选中的库和校验结果。上传、预览不修改现有插件、不加载包内代码。

固定来源更新与 ZIP 导入使用相同确认、进度和结果组件。没有可信固定发布源时只显示 ZIP 导入，不猜下载地址，也不把许可站当版本源。

## 3. 版本模型

| 名称 | 含义与事实源 |
| --- | --- |
| 官方内核版本 | 上游 CPA 发布信息，只用于发现与适配提示 |
| 本站发行版本 | 本站 main 的固定发行及已有镜像清单，包含内核基线与本站定制 |
| 服务器运行版本 | 实际运行镜像与活动记录相符后展示的版本；不是已下载或已发布的版本 |
| 插件候选版本 | ZIP 或固定发布源声明并通过静态核验的版本 |
| 插件已安装版本 | 已版本化落盘、配置已保存的版本，不代表活动实例已经切换 |
| 插件活动版本 | CPA 宿主当前实际加载并注册的版本；与 enabled、许可状态分别展示 |

本站发行元数据复用现有清单，补充所含上游提交及已验的插件配对。上游版本号更大、库能加载或包内摘要匹配，都不单独构成兼容结论。

版本检测在打开区域时按缓存有效期触发，也提供手动检查。请求只取发行元数据，不读取用户推理凭据，不调用模型；本期不建立定时任务。

## 4. 内核更新链路

```text
官方发布信息 → 发现新内核
                     ↓
固定上游基线 + 本站源码 + 目标上游 → 隔离适配与受影响验证
                     ↓
本站 main → 固定本站发行 → GitHub Actions 构建三角色资产
                     ↓
管理页面选择本站可安装版本 → 管理权限校验 → 一次维护确认
                     ↓
受限本机 Unix socket → 按需 systemd 更新任务
                     ↓
既有 mx-update：站点互斥 → 下载/预检 → 停态备份 → 切换
                     ↓
内部健康 → 恢复原入口 → 写完成回执与实际活动版本
                     ↓
Manager 恢复 → 页面读取原任务结果
```

### 宿主触发器的最小边界

- 采用本机 Unix socket 和按需 systemd 任务，不新增公网监听，不把 Docker socket 挂给 Manager。首次落位与站点登记合并做一次受控接入。
- 触发器只处理已登记站点的固定更新动作及任务状态查询。输入为本站已知发行 ID、操作 ID 和已确认维护范围；不接受任意 shell、下载 URL、宿主路径或自定义 Compose 命令。
- 管理接口沿用现有管理鉴权及会话保护，客户端推理 Key 无权限；socket 调用方按已登记的服务身份限制，不依赖浏览器字段自报身份。
- 用户确认绑定固定目标发行、资产清单、当前活动基线和维护影响。刷新页面或发现更新版本不更换目标；当前基线发生变化则要求重新预检，而不是静默执行另一版本。
- 同一确认重复提交返回同一操作；确实存在另一维护任务时返回忙碌及任务标识，不启动第二轮。
- 增加仅供宿主受控调用的非交互启动方式，保留 CLI 原人工确认。网页确认后不再卡在终端 `UPDATE` 提示，不用向标准输入拼接答案作为桥接方案。
- 更新子进程由 systemd 管理，状态写入既有私有轮次目录。Manager、浏览器连接或 HTTP 请求结束不终止更新；恢复后按原操作 ID 读取结果。
- 宿主重启或执行中断后先核实际阶段、容器和活动指针，展示“待恢复”并保留现场；不无证据重放维护步骤。恢复仍通过同一 updater 和命令入口，不另建恢复框架。

安装对象是本站组合发行，不直接安装官方裸 CPA。Manager、Worker 若未变也按现有发行清单一致管理，界面准确说明本轮影响。

## 5. ZIP 插件更新链路

```text
上传本地 ZIP / 选择固定来源版本
  → 私有暂存 → 静态预览 → 平台/身份/配对判断
  → 管理员确认固定候选及维护影响
  → 同站点更新互斥
  → 仅规范化指定插件库 → 既有商店安装服务
  → CPA 宿主排空/加载/注册 → 核活动版本及许可状态
  → 记录终态 → 释放互斥 → 页面展示结果
```

### 只导入插件，不执行整包安装

本次包实际库为 `plugin/dist/cpa-bps.so`，声明 `0.5.58`、`linux/amd64`、glibc。静态预览只识别清单和指定库，规范化为现有商店可使用的工件；安装仍写入既有版本化库路径。

不执行随包 `install.sh`、配置程序、烟测程序或面板升级脚本；不覆盖配套 Manager 页面，不写独立 `compose.bps.json`，不改本站活动 Compose 链。许可文件、账号、provider、稳定凭据引用与现有插件配置保留。

上传校验使用已有容量限制和清单校验机制，并对 ZIP 展开总量、越界路径、重复目标及多个候选库歧义做明确拒绝。未知平台、缺库、损坏包或不兼容配对停在预览；取消不产生产品配置变更。包内一致性通过与发布者来源可信分开显示，不新增无消费者的校验台账。

上传页面不在预览时运行库来“测兼容”。已验配对可引用相同输入的正式 CPA 宿主证据；不要求每个供应商版本先进入手工维护的白名单。静态条件合格但 ABI 或版本配对资料不足时显示“兼容性未验证”，管理员可在同一确认抽屉中对这个固定候选显式确认继续安装。普通安装确认不暗含该选择，也不设全局跳过开关；确认绑定候选、站点连接及维护影响。错平台、身份或完整性不符、已知不兼容仍拒绝安装。

单次确认不把兼容状态改成已验证。实际切换继续由正式宿主结果决定，保留原版本、配置和失败恢复路径；不自动执行在线模型试探。本轮只使用无网合成插件验证未验继续、缺确认拒绝及加载失败处理，不执行真实 0.5.58 许可或业务。

### 启停、重启与许可

- 升级保留原启停意图。原先停用的插件仍停用，可显示“安装完成 · 保持停用”，不要求为了验版本自动启用。
- 对启用中的插件，`installed` 后继续跟踪异步 reload；新版活动身份、版本和注册结果确认后才判定切换成功。只收到安装 HTTP 成功不关闭任务。
- 宿主逻辑热替换是否适用于 0.5.58 仍待实际验证。可热替换则走已有 quiesce；需要 CPA 重启时使用本站完整 Compose 链，不启动外部安装器。
- 确认页已包含重启影响的任务可按该范围继续；运行中才发现超出已确认范围的重启需求时进入“待确认重启”，保留任务和现场，不静默停止其他通道。
- 对该包，启动可能触发供应商许可联网检查；确认页单列其影响，保留原许可文件且不展示授权码。许可有效、BPS OAuth 可用、模型请求成功独立记录，安装流程不主动登录或发模型请求。
- 若活动版本已切换但许可失败，显示“新版已加载 · 许可异常”，业务可用性不标绿。原插件停用、缺许可与加载错误分别呈现。

## 6. 唯一站点互斥与任务状态

**共用后端站点级互斥，不是两个入口各锁各的，也不是只禁按钮。** 覆盖核心维护、现有商店直接安装、ZIP 安装及相关插件配置切换/重载入口；绕过 Manager 直接调用既有管理安装路由仍受约束。

互斥以站点为范围、操作 ID 为所有者，复用 `mx-update` 的站点锁和轮次状态；原 A 统一锁调用，不另造一套并行的插件锁协议。核心宿主任务持有到健康/入口恢复或失败终态；插件后端任务持有到异步 reload、许可结果及已确认必要重启结束。HTTP 返回不释放实际维护权。

跨进程的落地必须使 CPA 安装任务与宿主 updater 争用同一站点资源。采用受限共享锁目录或现有站点门禁的适配，实际选型以既有锁实现为准；不向 Manager 暴露整个宿主配置目录。需要重启 CPA 时由宿主按同一任务接续，未闭环任务先核现场再允许新写入，避免进程退出释放锁后开启相互覆盖的安装。

静态检查、下载和 ZIP 预览可并行，不获得维护权、不改变运行态；正式写入前再次检查已确认基线。取消只在维护前生效；已开始切换不把浏览器关页当作取消或盲目杀进程。

任务复用轮次记录，最小包含：操作 ID、类型、固定目标、确认时活动基线、阶段、实际活动结果、开始/结束时间、失败原因和恢复入口。敏感配置、代理口令、许可码、账号令牌不写进浏览器回执。

| 用户可见状态 | 可据此得出的结论 |
| --- | --- |
| 待适配 / 已知不兼容 | 发现候选，但不满足安装条件 |
| 兼容性未验证 | 静态条件合格、缺少运行配对证据；仅允许对此固定候选显式确认后继续，不冒充已验证 |
| 已上传 / 已预览 | 文件已暂存、静态检查有结果，产品未变更 |
| 可更新 / 待确认 | 固定候选符合进入本次维护的条件 |
| 准备中 / 维护中 / 验证中 | 后端任务进行中，不等同完成 |
| 待确认重启 / 待恢复 | 有明确未完成动作，保留原操作与现场 |
| 完成 / 安装完成且保持停用 | 分别满足运行切换或原停用意图的验收条件 |
| 失败 / 已加载但许可异常 | 显示事实分项，不把部分成功包装成业务可用 |

## 7. 失败与恢复规则

- 内核维护前失败不停止原服务；维护开始后失败沿用现有入口与应用停止、现场保全和定向恢复规则。新页面不另创自动回退逻辑。
- 插件预检失败不修改原插件；切换失败保留旧库、原配置、实际活动状态与回执。仅按已验证的数据兼容边界恢复，不把旧库存在等同整套数据可回退。
- 两类更新均不自动回灌数据库。遇到实际持久化格式或迁移变化，发行必须说明备份、兼容和恢复条件。
- 首次接入按既有站点资料核实活动链、持久目录和无凭据健康地址，不重做已经有效的部署调查。只读健康不隐式调用真实模型。

## 8. 最小验证与验收

本轮是文档设计，未运行以下产品测试。实施时先列实际改变的输入，旧专项输入未变继续引用；构建只在最终候选集中执行，不由执行、审查、验收各重跑一次。

| 具体要捕获的失败 | 验证路径 | 通过条件 |
| --- | --- | --- |
| 原包结构导致上传失败或误装面板 | 本次 0.5.58 目录结构；损坏、错平台、缺库、重复目标 ZIP | 正确提取指定库；异常停在预览；不执行脚本、不替换 UI |
| 预览/取消即改变插件 | 真实上传 API 与确认前后配置对照 | 暂存与产品写入分开，取消保留原版本和启停状态 |
| HTTP 成功但新版未运行 | 真实安装服务、CPA 宿主、异步 reload 成功/失败及停用样本 | 已安装与活动版本分层；失败和保持停用准确显示 |
| 独立锁导致核心和插件同时改配置 | 核心任务与商店直接 API、ZIP 安装并发，覆盖 reload 与重启阶段 | 全阶段互斥；重复操作复用任务；另一写操作明确拒绝 |
| Manager 重启导致更新丢失 | 网页确认后使用实际宿主触发器与 updater 重启 Manager | 任务继续；页面重连拿到同一任务与真实结果 |
| 目标漂移或维护影响被扩大 | 重复点击、刷新、更晚发行出现、实际基线变化、额外重启需求 | 原确认目标固定；基线变化重新预检；超范围动作待确认 |
| 错把官方最新版当本站升级 | 上游领先、本站待适配、检查失败、可安装本站发行四类样本 | 状态正确；安装仅选择固定本站发行 |
| 现有通道或许可配置受损 | 正式宿主身份/注册与本地模拟上游，稳定引用和配置对照 | 原通道规则与配置不变；许可/OAuth/推理状态不混同 |
| 失败后错误放流或回灌数据 | 维护前后故障注入与既有恢复入口 | 按原阶段保全，实际状态可追溯，无自动数据库回灌 |
| 功能存在于源码却页面不可用 | 部署候选中的真实设置页、插件页与上传抽屉 | 看得见入口、能预览/取消/确认、能看到真实终态；不是仅提供设计图 |

系统级更新验证用隔离本地站点和模拟外部服务，不触碰线上数据库或真实模型。商业许可联网、真实插件业务以及生产更新需要对应现场授权，离线证据不代替这些结论。

## 9. 实施顺序与责任

1. **共同基础与 ZIP 入口。** 原 A 收敛现有安装写路径、共享站点门禁和异步任务终态；前端沿现有插件页补上传/预览与状态，不新增页面体系。插件侧实际运行验证与库兼容资格同步闭环。
2. **核心发现与网页直达。** 在现有发行清单补版本元数据、设置页展示和固定目标确认；复用 updater，补窄宿主触发、独立任务、受控非交互入口与恢复后查询。
