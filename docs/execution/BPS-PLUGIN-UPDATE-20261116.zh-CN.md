## 本站已经具备的更新能力

已发布源码 `9dce11c613c5bc2c45d922cd2c021a7d5bba7a25` 已有 `/plugins?tab=store` 商店入口，前端 `pluginStoreApi.install` 支持指定来源和固定版本。安装链将库写入 `<plugins>/<系统>/<架构>/cpa-bps-v<版本>.so`，保存同一插件 ID 的配置并异步触发宿主 reload；不写 Compose，也不重建 Manager 镜像。

现有商店要求动态库处在 ZIP 根目录。本次整合包把库放在 `plugin/dist/cpa-bps.so`，因此不能直接将该整包当商店工件。最小改动是适配工件结构并复用已有安装链，不另造插件更新器。

宿主已有 quiesce 和逻辑热替换机制，但旧动态库映像保留至进程退出；busy 时可能返回需要重启。安装接口的 `installed` 只说明文件与配置保存及 reload 已派发，不是新版已注册、许可有效或推理通过。0.5.58 是否适合热替换需验证，既不宣称必定重启，也不承诺零中断。

## 推荐：同一更新区域，内核与插件分别管理

保留现有页面结构和 UI 风格：设置页展示 CPA 内核更新及插件摘要，现有 `/plugins` 页面明确提供“上传 ZIP”和固定来源更新入口，统一版本、兼容结论、更新时间与进度样式，不复制第二套安装页面。插件更新默认只更换插件，不重做凭证卡片、不替换整个 Manager 前端，也不改变 Kilo/Codex/BPS 的 Key 与调度契约。

支持两种来源：

1. **本地 ZIP 导入（待补）：** 现有安装链尚无本地 ZIP 上传入口。增加一个小型导入/预览入口，读取版本和平台、校验包中指定库并规范化为现有工件布局，随后复用同一插件安装服务。管理员确认后执行；导入文件不代表立即安装，不直接执行包内安装脚本。
2. **固定发布源：** 复用商店的来源和固定版本能力。有明确可信的 Releases/API 地址、符合合同的插件资产后检查新版本；无固定源时走上述 ZIP 导入，不猜下载地址，也不把许可站当下载源。本轮不自动上传这份二进制到公共 GitHub，不建立定时任务。

## 更新链路

```text
获取固定插件包 / 上传 ZIP
→ 识别版本、平台与实际文件
→ 核当前本站内核和插件兼容关系
→ 引用同一内核/插件配对的实际证据；资料不足标为兼容未验证，由管理员对固定候选显式确认继续，已知不兼容拒绝
→ 显示“可更新”及维护影响
→ 管理员一次确认
→ 与本站内核维护、商店直接安装共享后端站点互斥，进入既有插件安装链
→ 备份原插件和必要配置，保留持久数据
→ 版本化落盘并通过宿主切换，确需重启时使用原完整 Compose 链
→ 核插件版本、注册、许可状态与既有通道配置
→ 保存现场更新回执，实际终态后释放互斥
```

“库能加载”“宿主已注册”“商业许可有效”“BPS OAuth 可用”“真实推理通过”是不同结论，不合并为一个成功标志。本轮不为查更新执行登录、模型调用或付费探测。

上传与预览只做静态检查，不执行库或脚本；候选资格验证与正式确认安装分开。互斥覆盖 `installed` 之后的异步 reload 及已确认必要重启，HTTP 响应返回不等于任务结束。原停用插件保持停用，安装完成不冒充新版活动实例已验证。

### 实施范围

- 复用现有商店、插件管理与宿主生命周期，不默认扩展 `mx-update`，不新增外置 root 服务。插件安装与内核维护串行；确需改挂载或运行环境时才进入本站发布变更流程。
- 保持 `cpa-bps` 的宿主注册身份及已有 provider/凭据引用。保留当前插件挂载、许可文件、账号、原插件配置和持久数据。沿用版本化动态库路径，旧库保留供定位；升级模式保留原启停意图，现有安装入口设为 enabled 的行为需在预览与执行时明确处理，避免把升级变成隐式启用。
- 默认保留 CPA 镜像、Manager 前端/后端和 Worker。优先使用经验证的宿主切换；确需重启时显示 CPA 短维护影响，并使用站点既有完整 Compose 链。CPA 承载的其他通道也可能受这次重启影响，界面不宣称零中断。
- 如果新插件需要新内核或新增管理接口，先显示“需组合升级/待适配”；与内核更新合成一次已验发布和维护，不先装一半。兼容对象是本站内核提交/镜像与插件版本的配对，不只比较版本数字大小。
- 包内许可管理若能通过本站通用插件资源页承接则复用；若存在实际接口缺口，只补对应管理项并保持现有 UI，不采用整包面板替换。当前尚未证实许可操作已被现有页面承接。
- 页面复用现有管理权限和安装服务，客户端推理 Key 无此权限；目标为固定来源和版本，不接受任意 shell 命令。页面读取实际活动版本和注册/许可状态，不将一次安装 HTTP 成功显示为整轮升级成功。

外部安装器的 `--plugin-only` 会追加独立 `compose.bps.json` 并只重建 CPA。在已由 `mx-update` 活动指针管理的站点，这会与三应用须保持完整活动 Compose 链一致的约束发生冲突；因此不将该脚本作为默认更新入口。现有商店安装本身不改 Compose，不引入这种漂移。当前服务器是否已有活动指针仍以现场为准，本轮没有观测到实际漂移。

### 最小验证与失败处理

插件独立变更只补新二进制相关验证：实际 CPA 镜像中的加载/注册、可信宿主通道隔离、凭据引用、相关 BPS 请求契约及更新状态一致性。没有源码/接口输入变化的 Kilo、Manager 样式专项继续复用；组合升级则按实际共享接缝补测。

缺少许可时先确认受控拒绝和可诊断状态，不尝试绕过许可，也不将无网加载通过写成授权通过。真实许可联网与供应商请求放在明确授权的现场验收中。新版本若需要修改持久化数据，单独核兼容和回退边界，不把“旧 .so 已备份”写成完整数据可回退。

预检失败不触碰原服务。切换后失败保留旧二进制、配置、现场状态与回执，按实际数据兼容性定向恢复，不反复运行外部安装脚本或自动回灌旧数据。
